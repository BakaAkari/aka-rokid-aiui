# 真机测试记录

设备：国内版 Rokid Glasses，YODAOS-Sprite；Rokid AI Android。

本页用于验证**单页「连线诊断」**：语音唤起应用，唯一物理操作是确认键（开始/停止/重试）。一次完整诊断按顺序执行：**运行环境自检 → 公网 HTTPS 基线 → 手机 Tailscale MagicDNS HTTPS**，可选 Tailscale IP 作次级诊断。

> **诚实判定规则**：没有注入 MagicDNS HTTPS 端点时，总结果只能是「诊断未完成」（显示「Tailscale 端点未配置 / 诊断未完成」），**即使运行环境 9/9 或公网基线成功也不能显示 PASS**。只有当 MagicDNS 已配置，且运行环境、公网基线、MagicDNS 三项全部健康（HTTP 2xx）时，才显示「链路通过」。

## 操作模型与约束（硬约束）

- 语音唤起应用；**确认键为唯一物理操作**。不依赖方向键、上下键、触摸或菜单选择。
- 页面无可选择标签、无方向键导航、无并列功能入口。
- 确认：空闲=开始；运行中=停止；完成/失败=重试。Enter/GlobalHook 均视为确认；其他按键不承担选择。
- Backspace 仅在退出/返回前清理（取消探测、释放识别资源）。
- 错误详情限一行，可读，不泄露 URL query、token 或响应正文。

## 启动参数

- 只接受 `https://` 端点；http、token、Hermes key 不会被硬编码或接受。
- `baseline` / `url`：公网基线（缺省 `https://js.rokid.com/`）。
- `magicdns`：**主链路判定必需**；未提供则总结果应为「诊断未完成」。
- `ip`：可选，仅次级诊断，不参与主判定（证书通常不覆盖 IP 字面量）。

```
?baseline=https://js.rokid.com/&magicdns=https://<你的magicDNS域名>.ts.net/&ip=https://100.x.x.x/
```

## A/B/C/D 矩阵（手机 Tailscale × 眼镜网络）

目的：排除“公网正常，但不确定流量是否真的走了『手机 Mobile Proxy → Android Tailscale』”。通过启动参数注入一组 HTTPS 端点，按确认后顺序探测，明确区分三层：**公网基线**、**Tailscale MagicDNS HTTPS**、**可选 Tailscale IP HTTPS**。

### A：手机 Tailscale 开 + 眼镜 Wi-Fi 关

- 公网基线：HTTP 2xx，**健康**；
- Tailscale MagicDNS：HTTP 2xx，**健康**；
- 可选 Tailscale IP：仅在证书覆盖该 IP 时 2xx，否则允许 TLS 主机名校验失败（不参与主判定）；
- 终判：**链路通过**（三项核心均健康）。

> 这是“私网路径可达”的必要事实，不是充分条件——见“判定规则”。

### B：手机 Tailscale 关

- 公网基线：HTTP 2xx，**健康**（手机仍可走 Wi-Fi/蜂窝公网）；
- Tailscale MagicDNS：**超时 / 连接失败**，**不健康**；
- 可选 Tailscale IP：**超时 / 连接失败**，**不健康**；
- 终判：**诊断失败**。

### C：手机 Tailscale 开，但 Android 对 Rokid AI App 启用 VPN 绕过/排除（如可配置）

- 公网基线：HTTP 2xx，**健康**；
- Tailscale MagicDNS：**超时 / 连接失败**，**不健康**；
- 可选 Tailscale IP：**超时 / 连接失败**，**不健康**；
- 终判：**诊断失败**。

> 若系统不支持对单个 App 排除 VPN，则本行标为“不可测”。

### D：眼镜 Wi-Fi 开（作为对照）

- 公网基线：HTTP 2xx，**健康**（Wi-Fi 能上网即通）；
- Tailscale MagicDNS：通常**超时 / 连接失败**（眼镜未接入 tailnet），除非尾网全网段已含该 host 且在眼镜可达路由内；
- 终判：取决于 MagicDNS 是否可达；预期多为**诊断失败**。

## 判定规则（关键）

- **只有 A 私网成功且 B 失败，才能证明流量经手机 Tailscale。**
- **A 与 D 都成功但 B 仍失败**：不能直接下结论，需结合路由判断（眼镜实际走 Wi-Fi 还是手机代理；手机 Tailscale 的 exit node/子网路由/ACL；手机系统是否在 A 前提下为眼镜建了转发）。
- 工具本身只给出**诚实的事实**：每项 2xx=健康、其余=不健康；主判 PASS 仅在 MagicDNS 已配置且运行环境+公网+MagicDNS 均健康时给出；未配 MagicDNS 恒为**未完成**。工具**不替你做**“流量经手机 Tailscale”的推断——那是 A/B 对比的结论，仍需人结合路由判断。
